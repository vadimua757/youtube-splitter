# YouTube Splitter — дизайн

Дата: 2026-11-19

## Мета

Сервіс, який завантажує відео або аудіодоріжку з YouTube і, якщо вказано таймкоди з назвами, ділить результат на фрагменти. Спочатку працює локально, з можливістю пізніше опублікувати.

## Рішення

- Форма: HTTP API + проста веб-сторінка.
- Стек: Python 3 + FastAPI, `yt-dlp` (як бібліотека), `ffmpeg` (підпроцес).
- Запуск: локально та в Docker (`docker compose up`).
- Джерело таймкодів: текст у форматі опису YouTube; якщо його немає і ввімкнено `use_chapters`, то розділи (chapters) відео.
- Формати виходу: mp3 (перекодування), m4a/opus (без перекодування), mp4.
- Виконання завдань: вбудована фонова черга + SQLite (підхід A). Черга стоїть за інтерфейсом `JobRunner`, щоб пізніше замінити її на Celery/Redis без змін в API.
- Git не використовується.

## Компоненти

| Модуль | Призначення | Залежності |
|---|---|---|
| `app/timecodes.py` | Чиста функція: текст → `[(start_sec, title)]`; обчислення кінців фрагментів | немає |
| `app/downloader.py` | Метадані (назва, тривалість, chapters) і завантаження потоку через `yt-dlp` | `yt-dlp` |
| `app/splitter.py` | Нарізання за `[start, end)` через `ffmpeg`; очищення імен файлів | `ffmpeg` |
| `app/jobs.py` | Модель завдання, статуси, прогрес, SQLite-сховище, `JobRunner` | `sqlite3` |
| `app/api.py` | FastAPI-ендпоінти, валідація, авторизація, ліміти | усі вище |
| `static/index.html` | Веб-форма: посилання, формат, таймкоди, прогрес, посилання на файли | API |

### Формат таймкодів

Приймаються рядки на кшталт `0:00 Intro`, `3:45 - Song`, `1:02:03 – Назва`, `01. 5:10 Track`. Допускаються `m:ss` та `h:mm:ss`, роздільники ` `, `-`, `–`, `—`, порожні рядки ігноруються, нумерація перед таймкодом ігнорується. Рядки без таймкода пропускаються. Початки мають суворо зростати. Кінець фрагмента дорівнює початку наступного, кінець останнього дорівнює тривалості відео.

### Правило вибору фрагментів

1. Явний текст таймкодів має пріоритет.
2. Інакше, якщо `use_chapters=true` і у відео є розділи, беруться вони.
3. Інакше віддається один цілий файл.

## API

```
POST /jobs
  { "url": "...", "format": "mp3|m4a|opus|mp4", "timecodes": "text?",
    "use_chapters": false, "video_quality": "720|1080?", "video_mode": "fast|exact?" }
  → 202 { "job_id": "..." }   | 422 при помилці валідації

GET /jobs/{id}                → { status, progress, error?, title, parts: [{n, title, start, end, file}] }
GET /jobs/{id}/files/{n}      → окремий фрагмент
GET /jobs/{id}/download       → zip з усіма фрагментами (якщо фрагмент один, то сам файл)
```

Статуси: `queued → downloading → splitting → done | failed`.

Для `mp4` режим `fast` ріже за ключовими кадрами без перекодування (межі неточні), `exact` перекодовує (точно, повільніше). За замовчуванням `fast`.

## Помилки

Завдання переходить у `failed`; у відповіді є `error: {code, message}`.

- `VIDEO_UNAVAILABLE` — приватне, видалене, вікове обмеження, регіональне блокування.
- `INVALID_TIMECODES` — таймкод за межами тривалості або не зростає. Якщо тривалість відома лише після метаданих, помилка виникає на першому етапі завдання; інакше повертається 422 одразу.
- `DOWNLOAD_FAILED`, `SPLIT_FAILED` — збій `yt-dlp` або `ffmpeg`; у `message` короткий хвіст stderr. Один повтор лише для завантаження.
- `TOO_LONG` — відео довше за `MAX_DURATION_MIN`; `INTERNAL_ERROR` — непередбачений збій.
- Імена файлів: `NN - <назва>.<ext>`; з назви прибираються `/`, керівні символи, довжина обмежується; унікальність гарантує числовий префікс.

## Безпека та публікація

Усе вмикається змінними оточення; за замовчуванням вимкнено.

- Приймаються лише URL доменів `youtube.com`, `www.youtube.com`, `m.youtube.com`, `music.youtube.com`, `youtu.be`.
- Аргументи до `yt-dlp` та `ffmpeg` передаються масивом, без shell.
- Опційно: `API_KEY`, `MAX_DURATION_MIN`, `MAX_CONCURRENT_JOBS`, `FILE_TTL_HOURS` (автоочищення), rate limit.
- README застерігає, що завантаження з YouTube може суперечити його ToS; публічну версію слід обмежувати контентом, на який у користувачів є права.

## Тестування (TDD)

- `timecodes`: табличні юніт-тести (формати, роздільники, помилкові входи, межі).
- `splitter`: інтеграційні тести на згенерованому `ffmpeg` аудіо (синус ~10 с): кількість і тривалість фрагментів, імена.
- `downloader`: юніт-тести з підміненим `yt-dlp`, без мережі. Один smoke-тест на реальне коротке відео з маркером `network`, за замовчуванням вимкнений.
- `api`: `TestClient` з підміненим воркером: валідація, життєвий цикл, віддача файлів, zip, авторизація.
